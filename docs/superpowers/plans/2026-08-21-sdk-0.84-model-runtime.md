# SDK 0.84.2 migration — ModelRuntime + in-memory credentials (WS-2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade `@earendil-works/pi-coding-agent` 0.80.3 → 0.84.2 — clearing all 9 open Dependabot alerts — by migrating the session/auth layer from the removed `authStorage`/`modelRegistry` options to the new async `ModelRuntime`, without ever letting the operator's API key reach disk or the sandboxed agent's environment.

**Architecture:** The SDK removed `CreateAgentSessionOptions.authStorage` and `.modelRegistry` (in 0.80.8) in favour of one async `modelRuntime`. `AuthStorage` is no longer reachable (dropped from the root export and blocked by the package `exports` map), so the key must be supplied through a **junco-owned in-memory `CredentialStore`**. `ModelRuntime` exposes `getModel`/`registerProvider` directly, so it can back junco's existing SDK-free `RegistryLike` seam without importing `ModelRegistry` at all. The one structural change is that registry construction becomes **async**, which makes `resolveModelViaRegistries` async — a ripple contained to two call sites in `src/agent/session.ts` and five in `tests/modelSetup.test.ts`.

**Tech Stack:** TypeScript strict/ESM, vitest, `@earendil-works/pi-coding-agent` 0.84.2 (+ transitive `@earendil-works/pi-ai` 0.84.2).

**Spec:** GitHub issue #287. Its three named breakages (`session.ts:670` `authStorage`, `tests/session.test.ts:738` `AuthStorage`, `:767` `ModelRegistry.create`) are exactly the sites Task 3 rewrites.

`ModelRegistry` still exists as a sync facade (`new ModelRegistry(runtime)`) but this plan does **not** use it: `ModelRuntime.getModel`/`registerProvider` cover everything junco needs, so the migration removes one SDK symbol instead of adding one.

**Key design decision — seeding beats `setRuntimeApiKey`.** `ModelRuntime.setRuntimeApiKey` is now async and can reject with `CredentialSynchronizationError`. Seeding junco's own store so `read(provider)` returns `{type:"api_key", key}` reaches the same resolution result with no new failure mode and no async ordering hazard. (Verified in the compiled `model-runtime.js`: runtime keys live in a non-persistent `RuntimeCredentials` overlay and never reach the backing store — so neither path persists, but seeding is simpler.)

```ts
/**
 * An in-memory `CredentialStore` for the Pi SDK's `ModelRuntime`.
 *
 * THE SECURITY INVARIANT: junco must never write the operator's API key to
 * disk. `ModelRuntime.create` defaults `credentials` to storage file-backed at
 * `~/.pi/agent/auth.json` — and that backend CREATES the file — so every
 * `ModelRuntime.create` call in junco passes one of these instead. Nothing
 * here touches the filesystem; the Map dies with the process.
 *
 * Typed structurally against `@earendil-works/pi-ai`'s `CredentialStore`
 * (`dist/auth/types.d.ts:57-77`, verified against 0.84.2) rather than by
 * importing it: this module stays SDK-free so it is unit-testable, and the
 * cast to the SDK type happens at the single boundary in session.ts.
 */

/** Mirrors pi-ai's `ApiKeyCredential` (`dist/auth/types.d.ts:15-19`). */
export interface ApiKeyCredentialLike {
  type: "api_key";
  key?: string;
}

/** Mirrors pi-ai's `CredentialInfo` (`dist/auth/types.d.ts:34-37`). */
export interface CredentialInfoLike {
  providerId: string;
  type: "api_key";
}

export interface InMemoryCredentialStore {
  read(providerId: string): Promise<ApiKeyCredentialLike | undefined>;
  list(): Promise<readonly CredentialInfoLike[]>;
  modify(
    providerId: string,
    fn: (current: ApiKeyCredentialLike | undefined) => Promise<ApiKeyCredentialLike | undefined>,
  ): Promise<ApiKeyCredentialLike | undefined>;
  delete(providerId: string): Promise<void>;
}

/**
 * `seed` maps provider id → API key. Seeding up front (rather than calling
 * `ModelRuntime.setRuntimeApiKey`, which is async in 0.84 and can reject with
 * `CredentialSynchronizationError`) reaches the same resolution result with no
 * extra failure mode and no async ordering hazard.
 */
export function inMemoryCredentialStore(
  seed: Record<string, string> = {},
): InMemoryCredentialStore {
  const creds = new Map<string, ApiKeyCredentialLike>(
    Object.entries(seed).map(([providerId, key]) => [providerId, { type: "api_key", key }]),
  );
  return {
    read: async (providerId) => creds.get(providerId),
    list: async () =>
      [...creds.keys()].map((providerId) => ({ providerId, type: "api_key" as const })),
    modify: async (providerId, fn) => {
      const next = await fn(creds.get(providerId));
      if (next === undefined) creds.delete(providerId);
      else creds.set(providerId, next);
      return next;
    },
    delete: async (providerId) => {
      creds.delete(providerId);
    },
  };
}
```

- [ ] **Step 3: Rewrite `sdkRegistryOps` over `ModelRuntime`**

In `src/agent/session.ts`, replace the whole `sdkRegistryOps` function and its doc comment (`:491-510`) with:

```ts
/** The `ModelRuntime` surface junco uses, kept narrow so the cast at this
 * boundary is auditable (verified against 0.84.2 `dist/core/model-runtime.d.ts`:
 * `getModel`/`getModels`/`registerProvider`). */
interface SdkModelRuntime {
  getModel(providerId: string, modelId: string): unknown;
  getModels(providerId?: string): readonly unknown[];
  registerProvider(providerId: string, config: Record<string, unknown>): void;
}

/**
 * A models store that never touches disk. `ModelRuntime.create` otherwise
 * defaults to a `FileModelsStore` writing `models-store.json` NEXT TO the
 * operator's models.json — junco must not write there.
 */
const NOOP_MODELS_STORE = {
  read: async () => undefined,
  write: async () => {},
  delete: async () => {},
};

/**
 * Bridge from the SDK's async `ModelRuntime.create` to
 * `resolveModelViaRegistries`' SDK-free `RegistryOps` seam. Shared by
 * `makePiSessionFactory`, `getResolvedModelInfo`, and `listCatalogProviders`
 * so the cast-through-`unknown` lives in exactly one place.
 *
 * Every option here is load-bearing for the key-never-on-disk invariant:
 * `credentials` (default is file-backed `~/.pi/agent/auth.json`, and the
 * backend CREATES it), `modelsPath` stated explicitly (default is
 * `~/.pi/agent/models.json`), `refreshOnCreate: false` plus `modelsStore` (the
 * default file store can write beside the operator's models.json).
 * `allowModelNetwork` defaults to false and is left alone. Junco's three
 * cascade paths are all static, so skipping the refresh costs nothing.
 */
function sdkRegistryOps(
  ModelRuntimeStatic: { create(options: Record<string, unknown>): Promise<unknown> },
  credentials: unknown,
): RegistryOps {
  const make = async (modelsPath: string | null): Promise<RegistryLike> => {
    const runtime = (await ModelRuntimeStatic.create({
      credentials,
      modelsPath,
      refreshOnCreate: false,
      modelsStore: NOOP_MODELS_STORE,
    })) as SdkModelRuntime;
    return {
      find: (provider, modelId) => runtime.getModel(provider, modelId),
      registerProvider: (name, config) => runtime.registerProvider(name, config),
      backing: runtime,
    };
  };
  return { fromFile: (p) => make(p), inMemory: () => make(null) };
}
```
